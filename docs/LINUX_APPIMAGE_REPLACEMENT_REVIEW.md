# AppImage 文件替换与数据保留验收

日期：2026-09-07。本轮新增容器内手动文件替换验收，沿用既有候选包，没有重建、改版本或发布。

## 实现与 review

`scripts/smoke-linux-package-install.mjs` 增加 `--replace-from=<旧 AppImage>`，仅允许 `--bundle=appimage` 和 `--image`，拒绝与 DEB/RPM 升级模式混用。旧包与候选只读挂载，运行的是临时容器中的副本。

步骤：运行旧包并完成四格式转换 → 创建配置和原图样本 → 保存用户文件摘要 → 将候选复制到同目录临时文件并重命名到原运行路径 → 核对新运行文件与候选逐字节一致 → 新版转换、启动 → 复核升级前原图及旧输出，并核对语言/质量设置 → 删除运行文件 → 确认配置、原图与新旧输出仍保留。

Review 中落实的防护：

- 相同字节不能被记为成功替换；版本顺序不由文件名推定。
- 启动探测位于子 shell，不能以 `exit 0` 跳过后面的转换或保留验证。
- 转换沿用退出 0、完整成功记录及超时失败要求。
- 新版运行后再次对比原图与旧输出的原始摘要，不用新摘要掩盖改写。
- 原始文件只读挂载，只删除临时运行副本，不卸载宿主软件。

新增 2 项测试，其中真实 shell 流程分别覆盖正常替换、相同字节拒绝、新版转换失败、原图改写失败；同时覆盖宿主模式及错误包类型拒绝。应用和包管理器行为使用桩，复制、重命名、删除及摘要检查执行真实命令；真实候选结果另行记录。

## 范围与来源

- amd64：历史 0.2.8 → 本地 0.3.1，Ubuntu 22.04，ARM64 宿主上的 amd64 翻译执行。
- ARM64：历史本地 0.2.23 → 本地 0.3.1，Debian 13，匹配宿主架构的容器。
- 两组均为 release 候选、extract-and-run、虚拟显示；不启用 desktop-e2e。
- 证据目录：`artifacts/linux-amd64-2026-09-07/appimage-replacement/`，包含四包摘要、脚本摘要、镜像身份及日志。版本路径来源于既有候选记录，不代表对所有历史版本的覆盖。

## 未覆盖

本流程验证手动替换和删除单个运行文件，不代表 Tauri 自动更新器、更新签名、回滚、桌面集成卸载或 FUSE 挂载通过。虚拟显示启动不能代替真实显示器、GPU、读屏及安装件环保面板交互验收。配置只核对语言 zh-CN 与质量 37，不覆盖全部设置迁移。

没有上传、商店提交或公开发布；完整 Release 仍受 AGENTS.md 门禁约束。
