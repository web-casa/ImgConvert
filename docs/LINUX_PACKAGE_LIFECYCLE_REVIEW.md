# Linux 安装包升级与卸载验收

日期：2026-09-07。范围：ARM64 DEB/RPM 的 0.2.23 → 本地 0.3.1 候选。不是所有历史版本迁移、商店更新或公开发布证明；安装件字节不因本轮测试而改变。

## 新增能力

`scripts/smoke-linux-package-install.mjs` 新增 `--upgrade-from=<旧包路径>`。仅允许与 Docker `--image` 以及 DEB/RPM 同时使用，拒绝在宿主机卸载，也不对 AppImage 运行包管理器卸载。

流程为：核对前后包名、架构和稳定版本顺序 → 安装旧包并确认实际版本 → 旧包四格式转换及启动探测 → 创建配置与图片样本 → 安装新包并确认版本 → 检查包升级前后样本摘要 → 新包转换和启动探测 → 检查配置中的语言与质量值 → 卸载 → 确认包不再处于安装状态、命令和桌面入口已移除、测试用户文件保留。

所有安装件只读挂载，配置、缓存和数据目录位于临时容器内。测试配置使用真实 `com.ivmm.imgconvert/settings.json` 路径；原图样本是旧版实际生成的 PNG，旧版和新版输出存放在不同目录。

## Review 与防护

- 之前只有干净安装 smoke，无法证明升级与卸载行为；新增独立可选择的生命周期分支，不改变普通安装模式。
- 防止误卸载宿主程序：参数检查在定位安装件及调用 Docker 之前完成，生命周期模式必须有 image。
- 防止把重装或降级当升级：包名必须为 ImgConvert 的 `img-convert`，前后架构一致，版本必须为三个数字段的稳定版本，且新版本大于旧版本。
- 防止只验证包管理器返回码：分别查询安装后的真实版本，并执行新旧程序转换；转换沿用明确成功记录和超时失败规则。
- 防止卸载造成数据丢失：对配置、原图样本和新旧输出建立卸载前后 SHA-256 比较；程序启动允许规范化配置 JSON，因此升级包操作和启动后的保留检查分开进行。
- 新增回归覆盖宿主/AppImage 模式拒绝，以及同版本、降级、非法版本在安装目标包前被拒绝。

## 执行命令

在仓库根目录执行，旧包路径按实际文件提供：

```sh
node scripts/smoke-linux-package-install.mjs --bundle=deb --image=debian:13 --upgrade-from=/absolute/path/old.deb
node scripts/smoke-linux-package-install.mjs --bundle=rpm --image=fedora:42 --upgrade-from=/absolute/path/old.rpm
```

新包来自现有 target/release/bundle 对应目录。本次使用已归档的 0.2.23 包，及 [ARM64 候选记录](ENVIRONMENTAL_IMPACT_LINUX_PACKAGE_REVIEW.md) 中的 0.3.1 包。

## 边界

仅覆盖上述两个版本、两个发行版及 ARM64。配置断言覆盖语言 zh-CN 和质量 37 的保存值，不代表对全部设置、预设、旧配置损坏或 UI 迁移的完整验证。卸载采用 remove，不覆盖 purge。AppImage 的文件替换/FUSE、macOS/Windows、商店更新仍需独立验收；amd64 的后续结果见下节。GUI 按期限结束只证明启动探测，不能证明真实显示器、GPU 或无障碍功能通过。

两次容器任务均以退出码 0 完成。新旧安装件摘要及日志归档在本地 artifacts/linux-environment-2026-09-07/lifecycle/；新候选的摘要与上轮保持一致。

## amd64 后续验收与修复

本轮使用本地 `src-tauri/target/v028-artifact-audit/linux-amd64/` 内的 0.2.8 DEB/RPM，沿用其历史 SHA256SUMS 并实际核对通过；新包是 [amd64 候选记录](ENVIRONMENTAL_IMPACT_LINUX_AMD64_REVIEW.md) 中的 0.3.1。版本路径为 **0.2.8 → 0.3.1**，与上文 ARM64 的 0.2.23 路径不同。没有重新打包、改写安装件或改版本。

### P2：新版启动后的原图/旧输出变化会被新摘要掩盖（已修复）

旧流程在安装升级后核对升级前摘要，但新版转换和启动之后直接生成卸载基线。若这两个阶段意外改写原图或旧输出，新基线会接受变化，最后的“用户文件保留”声明超出检查覆盖。

现在为原图和旧输出单独保存升级前摘要，在新版转换、启动结束后再次核对，之后才允许创建卸载基线。配置仍允许 JSON 格式规范化，但必须保留语言和质量值；没有把配置的格式变化误报为图片损坏。

新增真实 shell 回归，运行生产流程中的转换/启动/摘要校验段，包管理器与应用行为使用临时桩。分别模拟未改写图片、改写原图、改写旧输出；后两种必须失败，第一种即使规范化配置 JSON 仍通过。这证明门禁可发现所述风险，不表示本次真实候选曾损坏用户文件。

测试新旧包只读挂载，输出和设置保存在临时容器中；宿主仅保存日志、源码工具摘要与安装件摘要。证据目录为 `artifacts/linux-amd64-2026-09-07/lifecycle/`。
