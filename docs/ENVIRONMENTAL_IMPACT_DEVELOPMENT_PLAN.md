让用户看见减少冗余图片数据的价值，并理解存储设备、运行用电和电子垃圾的环境影响。产品首先展示文件大小的真实变化，再提供可以检查假设的环境情景估算。

建议主题：**让图片更轻，让数字资源少一点浪费。**  
英文方向：**Smaller images. Less digital waste.**

## 2. 对外表述与计算边界

### 2.1 三种信息分开展示

1. **实际测量**：输出比输入小多少字节。使用“输出减少”，不默认声称已释放磁盘空间。
2. **假设情景**：如果输出替换云端原图，并保留指定时间，对应的存储运行用电与 CO₂ 分摊量差额是多少。
3. **用户自述已替换**：用户表示已完成替换，但依然是模型估算，不是设备测量或经认证的减排。

首版不使用“本次已减碳”“已节约多少度电”“抵消了碳足迹”等完成式结论。情景区间不是统计置信区间，也不是保证能够实现的上下限。

### 2.2 环境与替换状态

- 默认只显示输出大小变化；环境详情由用户主动展开，不弹出阻断转换的确认框。
- 展开后明确写明“云存储情景”，不根据操作系统、IP、图片来源或用户所在位置推测存储设备、数据中心地区及副本数。
- 本机硬盘、离线备份或未知存储环境只显示字节事实。用户仍可另行查看一个明确标注为假设的云存储情景，不能把它标成当前设备的效果。
- 替换状态默认为 `hypothetical`。`confirmed` 只表示用户自述；`retained` 不给出正向避免存储估算。
- UI 中“保留原图”指在所建模的同一存储环境中同时保留原图与输出，不把下载完成、点击保存或关闭窗口当作删除原图的证据。
- 功能不读取文件历史、不验证远程删除、不自动删除原图，也不请求新的权限来证明环保贡献。

### 2.3 暂不纳入数字的影响

压缩过程耗电、网络传输、硬件制造与运输、设备报废、延迟采购设备的效应，以及因为压缩而保存更多文件的反弹效应，均不加入首版数字。因此不能把结果称为净减排、全生命周期足迹或碳抵消。

硬件和电子垃圾的知识可以单独介绍，但不能从“少了若干 MB”直接推导“少制造了一块硬盘”或减少了特定数量的污染物。

复用官网现有 Svelte、多页面构建及样式体系。新增内容组件按路由加载，计算器只调用本地计算包。提供有意义的 HTML 静态正文：JavaScript 不可用时仍能阅读科普、来源和计算边界。

官网导航或页脚增加“环保与方法 / Environment & methodology”入口；只有新路由实际可用后，各产品才添加外链。

### 3.2 转换结果里的入口

默认结果示例：

> 输出净减少：9.5 MiB  
> 基于 3 个可比较的图片结果。  
> 查看存储环境估算

展开示例：

> 云存储情景  
> 如果这些输出替换云端原图，并保存 365 天……  
> 按当前假设，存储运行用电分摊差额：{energyRange}  
> 对应 CO₂ 分摊差额：{carbonRange}  
> 模型估算，非实测节电；未扣除转换耗电。

每个结果可查看其估算；批量界面同时提供一个汇总，避免每张图片自动展开卡片。设置包含保存时间、副本数和替换状态，并提供“恢复默认”。首版只在当前会话保留这些设置，不建立跨会话环保账本。

英文核心标签固定为 `Net output reduction`、`Cloud storage scenario`、`Estimated operational storage energy difference`、`Estimated operational storage CO₂ difference`。

### 3.3 首版不做

- 不做排行榜、全球真实用户贡献计数、积分、证书或碳交易。
- 不添加账号、分析埋点、上传接口、远程参数服务或地区定位。
- 不使用“相当于种树、开车、充手机”等需要额外依据的换算。
- 不做自动删除原图、远程替换或自动清理设备。
- 不为环保展示改变默认压缩质量、尺寸、编码器或队列调度。
- 不承诺同样画质或无损，除非具体转换设置确实支持该说法。

## 4. 模型、输入与数值展示

复用现有 `measureByteReduction`、`calculateConversionImpact`、`estimateStorageImpact` 和 `estimateDailyAccumulationImpact`，不在各端复制公式。

### 4.1 冻结参数与来源

首版沿用模型 `imgconvert.storage-operational-impact` / `1.0.0` 的历史情景，发布前补齐来源摘录、访问日期和参数选择记录：

| 参数          | 首版口径                                         | 来源与解释                                                                                                                                              |
| ------------- | ------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 存储能耗      | 0.65–1.2 Wh/TB-hour                              | [CCF 方法](https://www.cloudcarbonfootprint.org/docs/methodology/)的 HDD/SSD 历史系数，不代表所有设备实测范围                                           |
| PUE           | 1.10–1.185                                       | CCF 正文的历史供应商情景；该页 Azure 附录另列 1.125，不能混称为统一的当前实测值                                                                         |
| 电力 CO₂ 强度 | 473 gCO₂/kWh                                     | [Ember 2025 报告](https://ember-energy.org/app/uploads/2025/04/Report-Global-Electricity-Review-2025.pdf)中的 2024 年全球发电平均值，不代表用户当地电网 |
| 全球人口基准  | 60 亿网民                                        | [ITU 2025 估计](https://www.itu.int/en/mediacentre/Pages/PR-2025-11-17-Facts-and-Figures.aspx)，页面必须保留年份                                        |
| 电子垃圾背景  | 2022 年约 6,200 万吨，正式收集和回收记录占 22.3% | [ITU/UNITAR 2024 报告介绍](https://www.itu.int/en/mediacentre/Pages/PR-2024-03-20-e-waste-recycling.aspx)；这是全部电子垃圾，不是存储器专属数字         |

若更新系数、单位或公式，应升级模型版本、重新计算参考值并更新测试与说明，不能在运行时从网络悄悄替换参数。首版报告 CO₂，不将发电 CO₂ 系数包装成全生命周期 CO₂e。

### 4.2 界面默认值

- 单次云存储情景：365 天；副本数显示为可见的 `1–3` 情景范围，允许选择固定 1、2 或 3 份；默认“假设替换”。
- 全球情景：2025 年人口基准 60 亿；每人每天固定新增节省 **1 MB**；参与比例默认 100%；365 天；固定 **1 份**副本。提供 0–100% 参与比例、1–3650 天和 1/2/3 份副本控制。
- 单次手动容量输入：0–1 TB；保存时间允许 0–3650 天。零容量或零时间显示零估算，并解释没有有效存储量或时长。
- 首版不让全球“每日每人容量”自由扩大：现有 API 要求每日总字节数为安全整数，60 亿人 × 2 MB 已超过该范围。未来开放该输入前，必须先设计并测试大数计算契约，不能静默截断或放宽校验。
- 区间和固定值都要在结果附近展示副本、天数与电力系数；不能让个人与全球两种不同默认值看起来是同一个计算条件。

### 4.3 单位与累计规则

- 模型按十进制 SI 字节计算，`1 MB = 1,000,000 B`；现有工作台大小显示采用 KiB/MiB，继续准确标注单位。计算使用原始字节，不能回读已四舍五入的显示字符串。
- 电量按量级显示 Wh 或 kWh；中文可以附“度电”，并明确 1 度 = 1 kWh。排放按量级显示 mg、g 或 kg CO₂，避免微小结果被舍入成一个误导性的零。
- 估算保留内部精度，界面使用有限有效数字；特别大的全球总量属于情景估算，不能显示成精确测量整数。
- 全球计算使用逐日累计的 `D × (D + 1) / 2`，不把第 365 天新增的容量也算成已保存一年。
- 区分“期末减少的容量”“这段期间的运行用电差额”与“对应排放差额”，不混淆功率与电量。
- `NaN`、无穷、负值、非法范围、每日总量超出安全整数等输入均有可读错误；不能伪装成成功或显示 NaN。

### 4.4 比较资格与批量结果

首版延续 Web 的保守集合：静态栅格图片、转换成功、一个可比较输出。PDF 页面导出、SVG 栅格化、GIF/动画、多个输出、失败及取消的任务不参与环境估算。可以继续展示它们自己的文件信息。

同一情景与替换状态的参与项目先合计输入和输出，再计算净变化；较大的输出必须抵消较小的输出，不能只累计成功减小的文件。净值不为正时，不给正向环保数字。不同假设或保留状态不得直接相加。

汇总必须显示参与文件数和排除原因。用户选择“保留原图”时，仍可看输出大小差异，但环境估算显示不适用。部分项目被排除后，结果只代表参与子集，不能命名为“整个队列的实际节约”。

隐私与资源约束：

- 计算全部在本机完成，不记录文件名、路径、图片 URL、哈希或可关联用户的历史数据。
- 环保数字与设置首版为会话内数据。清空、关闭、取消、切换工作台及重复渲染不能产生跨会话累计或重复记账。
- “了解方法”只打开固定的本地化网址，不把文件大小、结果、设置或来源通过查询参数、片段、请求体或后台通信发送到官网。
- 直接进入官网只产生普通页面资源请求；计算器输入与交互不增加上报。官网专题页不添加分析、广告或远程计算服务。
- 不使用来源网页定位数据中心，不新增主机权限，不改变当前图片导入授权流程。
- 不引入图表框架、图片资源或 Worker 来运行简单乘法；图表如有必要使用轻量 HTML/SVG，并同步提供文本结果。

### 6.1 必须覆盖的行为

| 类别     | 最少验收案例                                                                                               |
| -------- | ---------------------------------------------------------------------------------------------------------- |
| 单文件   | 更小、相同、更大；失败/取消；静态图、动画、PDF、SVG、多输出；未知输入资格                                  |
| 批量     | 两个减小结果加一个增大结果；净值为负；混合替换状态；排除项目有解释                                         |
| 假设     | 默认假设替换、用户自述替换、保留两份；云存储与本机/未知环境                                                |
| 生命周期 | 删除队列项、清空、重试、重复下载、组件重建及侧栏/全屏切换均不重复累计                                      |

### 6.2 数值回归参考

以下是已存在模型的回归值，不是产品达成的成果：

- 单次 1 MB，365 天，默认 1–3 份副本：约 0.0062634–0.03737016 Wh、2.9625882–17.67608568 mg CO₂。
- 60 亿人每天新增 1 MB，365 天，单副本：期末 2.19 EB；第一年约 6.8772132–13.67747856 GWh、3,252.9218436–6,469.44735888 吨 CO₂。
- 相同全球情景的三副本运行估算是单副本的三倍；人口和字节口径不变。

数值按上文历史系数和方法计算；界面不照搬这些过多的小数位。任何更新模型的实施阶段都必须同步替换回归基线。

## 8. 本轮规划复核

| 发现的风险                       | 规划处理                                                        |
| -------------------------------- | --------------------------------------------------------------- |
| 将云存储系数套用到本机文件       | 默认字节事实；云存储模型需要明确的场景标签                      |
| 把压缩成功等同于删除原图         | 区分假设、用户自述与保留两份；不增加删除权限                    |
| 批量只统计变小的输出             | 同情景先净额汇总，更大输出必须抵消                              |
| 全球输入稍放大就超过安全整数     | 首版每日每人固定 1 MB，通过参与比例交互；扩展输入前先改计算契约 |
| 不同页面使用不同副本数却不说明   | 个人默认区间、全球默认单副本，参数始终与结果同屏                |
| PUE 来源正文与附录不同           | 记录历史系数的具体出处，不写“最新统一标准”                      |
| 对外方法链接携带当前结果数据     | 只打开固定网址，估算详情在产品内本地完成                        |
| 制造、电子垃圾数字冒充每文件减排 | 分开科普，全部电子垃圾统计不冒称存储器统计                      |
| 功能规划与当前送审包混淆         | 0.3.3 产物不变；下一版本实施后才更新对应商店承诺                |
